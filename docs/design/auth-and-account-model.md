# 账号与家庭成员模型设计

## 背景

系统既需要支持登录账号，又需要支持一个账号下维护多个家庭成员。如果直接把登录邮箱和密码存放在家庭成员对象上，会把“登录主体”和“被管理对象”混在一起，导致权限边界不清晰。

## 设计目标

1. 将登录主体与业务主体拆分。
2. 支持一个账号维护多个家庭成员。
3. 为账号隔离和后续权限扩展保留明确边界。

## 核心方案

当前采用如下模型：

- `Account`：登录主体，持有 `email` 与 `passwordHash`
- `User`：家庭成员档案，归属到某个 `Account`

模型关系为：

`Account -> User`

在此基础上，`User` 继续向下关联就诊与医疗记录。

## 设计收益

- 登录身份清晰，认证逻辑集中在账号层。
- 家庭成员管理与登录认证解耦。
- 后续若要扩展账号级权限、邀请协作、组织归属，会比直接耦合在 `User` 上更容易演进。

## 边界与限制

- 当前仍是单账号拥有多个家庭成员的模式，尚未扩展到多角色协作模型。
- 当前没有更细粒度的角色授权，主要依赖账号级隔离。

## 关联代码

- `apps/server/prisma/schema.prisma`
- `apps/server/src/modules/auth/`
- `apps/server/src/modules/user/`

## 后续可扩展方向

- 引入账号级角色与权限。
- 支持家庭成员共享或协作管理。
- 支持审计日志记录谁对哪个成员进行了操作。
